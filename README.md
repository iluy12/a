# עילוי זמנים — POC ל-S10PRO

אפליקציית בדיקה (proof of concept) שמממשת את מה שסיכמנו: התראה 10 דק' לפני
סוף זמן קר"ש וסוף זמן מנחה, מחושבת אופליין (ספריית KosherJava zmanim),
עם התאמה לאזור גיאוגרפי דרך GPS חד-פעמי בכל מחזור. אין קריאת רשת בכלל.

**זו לא האפליקציה הסופית.** המטרה עכשיו: לבדוק אם אפשר בכלל להתקין (sideload)
APK חיצוני על ה-S10PRO, לפני שממתינים לתשובת ויקי.

## מה עוד פתוח מול ויקי
ויקי אישרה שיש Google Play Store על השעון, אבל לא אישרה sideload של APK
חיצוני (לא מה-Store). השאלה המדויקת שעדיין מחכה לתשובה:
> Can we sideload a custom APK file directly (not through Play Store),
> for example via ADB or file manager?

עד שיש תשובה — הבדיקה הבאה (עם ADB) היא בעצם הדרך הכי מהירה לגלות את זה
בעצמך, בלי להמתין יומיים.

## הדרך הכי פשוטה — בלי להתקין שום דבר (GitHub Actions)
אם אין לך רקע בפיתוח, זו הדרך המומלצת. GitHub בונה את ה-APK על השרתים שלו,
בחינם, ואתה רק מוריד את התוצאה מהדפדפן:

1. פתח חשבון חינמי ב-https://github.com (אם אין לך).
2. צור repository חדש: כפתור ירוק **"New"** בעמוד הראשי → תן שם (למשל
   `iluy-zmanim`) → **Create repository**. אין צורך לסמן שום דבר נוסף.
3. בעמוד הריפו החדש לחץ **"uploading an existing file"** (או Add file →
   Upload files).
4. **גרור לשם את כל התוכן** מתוך תיקיית `iluy-zmanim` שחילצת מהזיפ — כולל
   התיקייה `.github` (היא מוסתרת בחלק ממנהלי הקבצים, ודא שהיא נגררת גם היא).
5. לחץ **Commit changes** בתחתית העמוד.
6. עבור לטאב **Actions** למעלה בעמוד. אמור להופיע ריצה בשם "Build APK" —
   עיגול צהוב מסתובב = עדיין בונה, ✅ ירוק = הצליח (לוקח כ-3-5 דקות).
7. אחרי שהריצה מסתיימת בהצלחה, לחץ עליה, גלול למטה ל-**Artifacts**, ולחץ על
   **iluy-zmanim-debug-apk** כדי להוריד zip קטן שבתוכו קובץ ה-`app-debug.apk`.
8. את הקובץ הזה (רק אותו, לא את הזיפ שסביבו) שולחים לשעון בדיוק כמו שכבר
   תרגלת — מייל / UC Browser / Bluetooth.

אם הריצה נכשלת (❌ אדום) — לחץ עליה, פתח את "Build debug APK" ותעתיק את
שורת השגיאה האדומה כדי שאפשר יהיה לתקן.

## דרך חלופית — פיתוח מקומי (רק אם יש לך מפתח/רקע טכני)
1. התקן [Android Studio](https://developer.android.com/studio) (חינמי).
2. פתח את התיקייה `iluy-zmanim` כפרויקט קיים (Open an existing project).
   Android Studio ייצור אוטומטית את ה-Gradle wrapper החסר ויסנכרן.
3. המתן לסנכרון (מוריד תלויות מ-Maven Central, כולל ספריית ה-zmanim).
4. Build → Build Bundle(s) / APK(s) → Build APK(s).
5. ה-APK ייווצר תחת: `app/build/outputs/apk/debug/app-debug.apk`

אם `com.kosherjava:zmanim:2.5.0` לא נמצא, בדוק את המספר המדויק בעדכון האחרון ב-
https://mvnrepository.com/artifact/com.kosherjava/zmanim ותעדכן ב-`app/build.gradle.kts`.

## שלב 2 — הפעלת מצב מפתח בשעון
זה הצעד הכי לא ודאי — שעונים זולים מבוססי ASR8601 לפעמים לא חושפים
"Developer Options" בממשק הרגיל. נסה:
1. הגדרות → אודות השעון → לחיצות חוזרות על "מספר build" (כמו בטלפון רגיל).
2. אם זה לא עובד — שאל את ויקי איך מפעילים USB debugging / ADB על הדגם הזה,
   זו בעצם אותה שאלה כמו ה-sideload.

## שלב 3 — חיבור וסנכרון עם ADB
```bash
# ודא שכלי הפלטפורמה של אנדרואיד מותקנים (מגיעים עם Android Studio)
adb devices
# אמור להופיע device ID של השעון (אם מחובר ב-USB, או ב-WiFi דרך adb connect)
```

אם השעון לא מוצג — ייתכן שאין לו כבל USB-data תקני (חלק מהשעונים הזולים
מגיעים רק עם כבל טעינה), או שצריך `adb connect <ip>:5555` דרך WiFi אם יש
כזו אופציה בהגדרות המפתח.

## שלב 4 — התקנה בפועל
```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
- **הצליח** → זה עונה על שאלת ה-sideload בעצמך, לפני התשובה מוויקי. אפשר
  להתקדם בפיתוח מיד.
- **נכשל** (למשל `INSTALL_FAILED_...` או השעון לא מזוהה בכלל) → זה כן צריך
  את התשובה של ויקי, כי כנראה יש נעילת firmware.

## בדיקה על השעון עצמו
1. פתח את האפליקציה "עילוי זמנים" מרשימת האפליקציות.
2. לחץ "בקש הרשאת מיקום" ואשר.
3. לחץ "בדיקה מיידית" — זה מריץ את כל השרשרת (חישוב לכל האזורים → GPS חד-פעמי
   → זיהוי אזור → התראה) תוך שניות, בלי להמתין לזמן האמיתי של היום.
4. אמורה לצאת התראה: "בדיקה — עוד 10 דק' סוף זמן קר"ש (מדומה)" עם שם האזור שזוהה.
5. לחץ "תזמן התראות יומיות" כדי להפעיל את השרשרת האמיתית (חישוב 04:30/11:30).

## מגבלות ידועות של ה-POC הזה
- **Google Play Services לא ודאי בשעון הזה** — לכן הקוד משתמש ב-
  `android.location.LocationManager` הבסיסי ולא ב-FusedLocationProviderClient,
  כדי לא ליצור תלות שאולי לא קיימת על הצ'יפסט ASR8601.
- רשת האזורים (`RegionTable.kt`) כוללת 18 אזורים המכסים את ישראל. אפשר
  להרחיב/לצמצם בלי לגעת בשאר הקוד.
- אין עדיין מסך הגדרות אמיתי (בחירת אזור ידנית, ביטול GPS וכו') — זה שכבת
  UI שכדאי להוסיף אחרי שהשאלה הטכנית עם ויקי נסגרת.
- זמן מנחה מחושב לפי "מנחה קטנה" (השיטה השמרנית/מוקדמת יותר) — אם צריך
  שיטה אחרת (למשל לפי הרב אלקבץ) זה שינוי שורה אחת ב-`DailyZmanimCalculator.kt`.
